## Per slice (as for s402 and s405)
1. Cut the worktree: `git worktree add -b feature/<id>-<slug> .worktrees/<id> main`. Begin the relay run and record the orchestrator and implementer steps.
2. Implementer brief, in the foreground: start, re-anchor, red tests, implementation, mutation check, full suite, `check`. No note or handoff.
3. Reviewer, then a fix round, then a combined gate on the resumed reviewer. Owner-tagged findings come to the owner via AskUserQuestion when they change the fix. Otherwise they go to the end summary.
4. On PASS, the implementer runs the note and `handoff --render --check`. I commit on the branch and file the later notes in a second commit.
5. Land:
   - `git fetch`. If main moved, merge main into the branch (rebaselining the golden if needed), render, check, and rerun the full suite on the merged branch.
   - `merge --ff-only`, `relay-run end`, `slicer land`, commit "ID done", remove the worktree and the branch.
6. No push. Commit messages carry no attribution lines (global CLAUDE.md).

## Stop conditions
A gate fails three times, the spec turns out ambiguous or wrong, an owner question is marked blocker, or a permission denial. Each pauses only that lane.

## Verification
- Each slice: the full suite green on the merged branch, `slicer check`, `git diff --check`.
- End of wave:
  - On main: the full suite, `slicer check`, `PYTHONPATH=src python3 -m slicer ai relay` (v10 text reads coherently), `slicer list` (the v1.17 pass is empty).
  - The CHANGELOG has a single coherent v10 entry under Unreleased.
  - A summary to the owner: per-slice verdicts, rounds, owner-needed items, later notes filed. Pushing and the release remain the owner's.
