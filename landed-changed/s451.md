category: Added

`slicer merge-slice` and the `slicer-slice` merge driver for slice JSON under `.slicer/slices/` (open slices, and the done and retired folders below it). Two branches that each `slicer edit` one slice now merge without hand resolution: object fields merge by name, sections by heading and occurrence, and `notes` as a union by exact text (the lines both sides kept in base order, then the lines only ours added, then the lines only theirs added). A value both sides changed differently, a section one side removed and the other edited, a heading both sides added with different content, or sections both sides reordered differently is refused with `merge_conflict` (exit 2) naming each place, such as `sections/Implement/body`, and the file is left as it was; keep one side with `git checkout --ours|--theirs` and re-apply the other with `slicer edit`. `slicer setup-git` and the hint `slicer init` prints now give eight `git config` lines (two more, for `merge.slicer-slice`). The `.slicer/.gitattributes` template gains `slices/*.json` and `slices/*/*.json` lines; an existing project takes them with `slicer setup-git --attributes`, and a clone needs the two new `git config` lines before Git calls the driver. `slicer verify` warns when the driver is not configured in a clone with sibling worktrees (s451).
